## 0. 이 문서를 읽는 법

- **담당자 컬럼은 화면의 고정 소유자**를 뜻한다. 담당 외 화면을 임의로 수정하지 않는다.
- **A는 담당자 컬럼에 없다.** A는 고정 소유 화면이 없고, **L이 인계를 선언한 화면**의
  디자인·디테일을 맡는다. 인계 시점부터 그 화면은 A 소유이며 L은 이후 수정하지 않는다.
  인계 기준은 **데이터 연결 + 로그 삽입 완료 시점**이다. 디자인이 덜 됐어도 넘긴다.
- **`[미확정] B 또는 C`** 는 담당 영역만 정해졌고 분담 방식이 정해지지 않은 화면이다.
  한 명이 전부 맡을 수도, 둘이 나눌 수도 있다. **작업 전에 사람에게 담당자를 먼저 확인한다.**
- **`[미확정]`** (영역 표기 없음)은 v3 이후 새로 생긴 화면이다. 04 v3 §4 와 CLAUDE.md 13장의
  배정표에 없어 이 문서가 담당을 정하지 않는다. **작업 전에 사람에게 확인한다.**
- **구현 상태** 열: `구현` = 화면이 있고 다른 화면에서 들어오는 경로가 있다 /
  `placeholder` = 라우트 파일은 있으나 뼈대만 있다 / `고아` = 파일은 있으나 부르는 곳이 없다 (§3-1).

자세한 소유·인계 규칙은 `CLAUDE.md` 13장을 따른다.

> **🔁 변경 §0 (v3 → v4)**
> - **이전**: 담당 표기 3종(L · `[미확정] B 또는 C` · A 인계)
> - **문제정의**: v3 에 없는 화면이 16개 생겼는데 담당 배정 결정이 없다. 코드 주석에 담당 언급이 있어도 그것은 배정 결정이 아니다
> - **의사결정**: `[미확정]` 표기와 **구현 상태** 열을 추가한다. 담당 배정은 이 문서가 하지 않는다 · 2026-09-18 · 18 §11
> - **상태**: 확정 (표기) / 배정 = **[검토 필요]**

## 1. 라우트 원칙

- 상세 리소스는 `:tripId`, `:groupId`, `:postId`, `:transactionId`, `:categoryId`, `:notificationId`, `:token`, `:inviteId` 를 사용한다.
  (`CLAUDE.md` 6장 식별자 계약과 동일한 이름을 쓴다)
- 팝업·바텀시트는 별도 라우트가 아닌 화면 내부 상태로 처리한다.
  **나가기(MEM) · 취소 동의(CXL) · 여행 유형 결과 오버레이도 라우트가 아니다.** (§6)
- 담당자 미지정 화면은 임의 배정하지 않는다.
- **Expo Router 파일 경로를 병기한다.** 논리 라우트(`:param`)와 실제 파일 경로(`[param]`)는
  표기만 다르고 같은 것이다.
- **하단 탭 4개**(홈·모임·커뮤니티·마이페이지)는 `app/(tabs)/` route group 아래 둔다.
  `(tabs)` 는 **URL에 나타나지 않으므로** 논리 라우트는 `/`, `/groups`, `/community`, `/me` 그대로다.
  상세 화면은 `(tabs)` 밖에 두어 탭 위에 Stack으로 쌓이게 한다 — 탭바가 사라지고 뒤로가기가 생긴다.
- **정적 라우트가 동적 라우트보다 우선한다.** `app/groups/personal.tsx` 는 `app/groups/[groupId]/index.tsx` 보다
  먼저 매칭된다. 그래서 개인 여행 상세는 `/groups/personal` 로 둔다. (`app/groups/personal.tsx:13`)
- **진입 param** 은 화면 ID 를 늘리지 않고 한 라우트 안의 분기로 쓴다. 코드에서 확인된 것:
  `/trips/new/owner?entryPoint=` · `/trips/:tripId?cxl=vote|progress` · `?cancel=1` · `?from=my-trips&filter=` ·
  `/trips/:tripId/edit?focus=requests` · `/trips/:tripId/funds?scan=receipt` ·
  `/trips/:tripId/funds/transactions?filter=&categoryId=&transactionId=` ·
  `/trips/:tripId/funds/connect?fromGroupId=` · `/trips/:tripId/insurance?placement=&fromCategory=` ·
  `/me/trips?filter=planning|traveling|past` · `/me/notifications/:id?source=db|push` · `/login?next=` · `/community?destination=`
- **로그인 전 열리는 세그먼트는 `login` 뿐**이고, 탈퇴 대기 계정은 `withdrawal-pending` 만 연다. 둘 다 `app/_layout.tsx` 가드가 정한다.

> **🔁 변경 §1 (v3 → v4)**
> - **이전**: 식별자 5종, 탭 그룹 원칙
> - **문제정의**: 초대·알림 라우트가 생기며 식별자가 늘었고, 정적/동적 우선순위 때문에 개인 여행 상세가 `/groups/personal` 이 됐다. 진입 param 이 문서에 없어 같은 화면의 분기를 새 화면 ID 로 오해할 자리가 생겼다
> - **의사결정**: 식별자 3종 추가, 정적 우선 원칙과 진입 param 목록 명시 · 2026-09-18 · `router.push(` 전수 grep
> - **상태**: 확정
