## 0. 로그인·온보딩 (신설)

```text
앱 실행
→ 세션 없음 → /login
   ├─ 카카오 로그인
   ├─ 구글 로그인
   └─ 이메일 (같은 화면에서 로그인 ↔ 가입 · 인증 코드 전환)
→ 세션 있음 → 홈
   ├─ 여행 0건 (신규) → 홈 빈 상태 + '둘러보기' 카드(OnboardingEntryCard)
   │      → /onboarding (캐러셀) → '첫 여행 만들기' → 2-1 (entryPoint = EMPTY_STATE)
   └─ 여행 있음 → §1 전체 흐름
```

- 로그인 화면은 `/login`(`app/login.tsx` · `components/auth/LoginView.tsx` · `EmailAuthView.tsx`). 이용약관·개인정보처리방침 링크가 있다.
- 세션이 없으면 여행 생성 저장이 차단된다(`AuthProvider`). 개발용 고정 사용자(`DEV_USER_ID`)는 사라졌다.
- 회원탈퇴 대기(`PENDING_WITHDRAWAL`) 계정은 `/withdrawal-pending` 으로 안내되고, 30일 안에 취소할 수 있다. 로그인만으로 자동 복구되지 않는다.
- `__DEV__` 에서만 "둘러보기"(미리보기) 진입이 있다. DB 접근이 없는 개발 편의 기능이다.

> **🔁 변경 (v1 → v2)**
> - **이전(v1)**: 해당 절 없음. 흐름은 "서비스 진입 → 홈"에서 시작했고 화면목록에도 LOGIN 이 없었다.
> - **문제정의**: 문서에 인증 화면이 통째로 없었다(18 §7-1). 첫 사용자가 무엇을 할지 몰랐다(18 §7-3). 로그인 없이 시드 사용자로 저장하던 임시 구조가 해소됐는데 표기가 그대로였다(18 §2-19).
> - **의사결정**: 카카오·구글·이메일 로그인 코드 선행 · `app/login.tsx` (18 §7-1) / 개발용 미리보기 코드 선행 (18 §7-2) / 온보딩 코드 선행 2026-09-17 · `app/onboarding.tsx` (18 §7-3) / 실제 세션 필수 코드 선행 · `app/trips/new/owner.tsx` (18 §2-19) / 탈퇴 대기 `15_회원탈퇴정책_v1.md` 2026-09-17 (18 §10-8).
> - **상태**: 코드 선행(문서만 갱신) / [검토 필요] 온보딩은 `useScreenView` 를 부르지 않는다(`SCREENS` 상수 없음 · `app/onboarding.tsx` 주석) · 획득 퍼널(`login_completed`)은 아직 기록되지 않는다(README §6)

## 1. 전체 흐름

```text
서비스 진입 (§0 로그인)
→ 홈
├─ 진행 중 여행 (PLANNING · TRAVELING · CANCEL_PENDING) → 2-2 여행 홈
├─ 지난 여행 (ENDED · SETTLED) → 2-2 종료 상태 여행 홈 (ENDED 는 카드에서 바로 결산)
├─ 답해야 할 일 배너 → 초대 랜딩 / 참여 의사 수락 / 취소 동의
├─ 🔔 알림센터
└─ 새 여행 (FAB) → 2-1 여행 생성

2-1 여행 생성
→ 2-2 여행 준비 홈 (PLANNING)
→ 2-3 예산 상세
↔ 2-4 여행자금/입출금 (영수증 스캔 · AI 분류)
→ [출발일] 자동 TRAVELING — 매일 21:00 지출 리마인드
→ [종료일 + 1] 자동 ENDED — 결산 안내
→ 2-6 여행 결산 → 확정 (SETTLED)
→ 2-5 여행 유형 결과 (9종)
→ 다음 여행 개인화

(모임은 별도 생성 없음)
개인 여행 2-2 → 초대 링크 발급 → 상대가 참여 의사 → 여행장 수락
→ 모임 생성 + PERSONAL → GROUP (§8-1)
```

- 모임 탭은 하단 탭에 있다. 홈에는 모임 바로가기가 없다.
- `CANCEL_PENDING` 여행도 홈 진행 중 목록에 보인다. 동의할 사람이 들어갈 길이 그 목록뿐이다(`isTripOngoing`).

> **🔁 변경 (v1 → v2)**
> - **이전(v1)**: "서비스 진입 → 홈 → 진행 중 / 종료 / 모임 → 모임 상세 / 새 여행" · "2-4 → 여행 종료 → 2-6".

## 2. 2-1 여행 생성

1. `누구와 가나요?` — `/trips/new/owner` (TRIP-01)
   - 개인
   - 기존 모임
   - 신규 모임: **모임 이름만** 입력. 멤버는 초대 → 참여 의사 → 수락으로만 늘어난다.
   - 결산 완료 과거 여행이 1건 이상이면 개인·기존 모임 **둘 다** "지난 여행 데이터 반영" 토글(기본 ON)을 보여준다. 안 만져도 진행된다.
2. 여행 기본정보 — `/trips/new/basic` (TRIP-02)
   - 여행지: **13개 해외 목적지 목록**에서만 고른다. 지역 세그먼트 필터 + 검색창(목록을 걷어내지 않는 필터) + 도시 칩. 목록 밖 도시 직접 입력은 없다.
   - 일정
   - 인원: 기존 모임 = 멤버 수, 신규 모임 = 2명 기본, 개인 = 1명(인원 섹션 없음)
   - 여행 스타일은 여기서 묻지 않는다.
3. 여행 예산·자금 설정 — `/trips/new/budget-fund` (TRIP-03)
   - **추천 예산이 기본값으로 먼저 나온다.** 방식 선택 카드는 없다. 히어로에서 "직접 입력"으로 전환할 수 있다(`budget_method_selected` 는 이 전환에서 기록).
   - 추천 방식일 때만 **여행 스타일**(budget / standard / comfort)을 고른다. 스타일은 카테고리별 배수로 금액에 바로 반영된다(보험은 스타일 무관).
   - 예산 구성 편집: 근거 상품 **체크박스**(항공은 단일 선택) · **예비비 비율** · 카테고리별 AI↔직접 전환 · 지난 여행 편차 개별 제외. 근거 상품명·금액은 LLM(`budget-products`)이 현지화하고 ±40% 가드레일 안에서만 반영된다.
   - 직접 입력 경로는 입력한 총액을 카테고리로 배분하고 아래 예산 구성에서 고친다.
   - 여행자금 **3택**: 연결된 계좌(MOCK) / 금액 직접 입력(MANUAL) / 0원으로 시작(ZERO). 신규 계좌 개설은 여기서 하지 않는다. 기존 모임에 연결 계좌가 있으면 자동 선택된다.
   - 고른 근거 상품은 생성 시점에 세부 계획 항목(`planItems`)으로 저장된다.
   - 저장은 3단계에서 한 번에 한다(1·2단계는 DB 에 쓰지 않는다).
4. 생성 완료 → 2-2

> **🔁 변경 (v1 → v2)**

## 3. 2-2 여행 준비 홈

**역할:** `우리 여행 준비가 지금 어느 정도 됐지?`에 답하는 종합 요약 화면. 라우트 `/trips/[tripId]`.

- 상단 배너 3종: **승인 대기**(참여 의사 도착 · 여행장) / **취소 요청 중**(동의 필요) / **아직 나 혼자**(초대 권유). 초대 권유 모달은 1회.

## 6. 여행 종료·결산

1. **자동 종료**: 종료일 다음 날부터 여행 홈 진입 시 `ENDED` 로 자동 전환(`closeTripIfEnded`) → `settlement_prompted(trigger=auto)`. 수동 종료 버튼은 없다. 서버 배치가 없어 앱을 열어야 전환된다. 홈 지난 여행 카드에서도 바로 결산으로 간다.
2. 미분류/누락 거래가 있으면 거래 추가·분류 수정. 결산 화면(SETTLE-01)은 **미분류 거래 → FUND-04(확인 필요 필터)**, **지출 미연결 계획 → 해당 BUDGET-02** 로 보내며 두 값을 따로 센다.
3. 2-6 결산(`/trips/[tripId]/settlement`)에서 전체 및 카테고리 예상 vs 실제 확인
4. 결산 확정 → `SETTLED` + `settlements.confirmed_at`. 확정 시점 값을 스냅샷으로 보존한다. 확정은 사용자 확인 후에만(자동 확정 없음).
5. 개인/모임 데이터 누적
6. 2-5 여행 유형 결과 생성(여행 홈에서 자동 생성 · 1회 저장)
7. **결산 공유**: 정산 카드 PNG + 명세서 PDF 공유(`lib/settlement/reportHtml.ts`)
8. 지난 여행 저장, 같은 멤버로 다시 만들기
9. `SETTLED` 이후는 전 화면 읽기 전용. 되돌리기는 없다.

   ├─ 거절
   └─ "참여 의사 보내기" → JOIN_REQUESTED 알림 → 여행장
        (인원이 찼어도 보낼 수 있다 · 여행장이 인원을 늘리면 수락된다)

[취소] 여행 홈 → 취소 요청 → CANCEL_PENDING (홈 진행 중 목록 유지)

[회원탈퇴] /me/account → 30일 유예 (PENDING_WITHDRAWAL) → /withdrawal-pending

   · 공동 여행 기록/금액/정산 불변 · 30일 후 cron 이 최종 처리 (tombstone)
