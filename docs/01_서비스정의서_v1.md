| 항목 | 내용 |

## 1. 서비스 정의

> 여행 전 필요한 비용을 계획하고 여행자금을 준비하며, 실제 소비 경험을 다음 여행의 더 나은 예산으로 연결하는 여행 금융 서비스.

TripPot은 단순 여행 일정 플래너나 모임통장 관리 앱이 아니다. 사용자가 `얼마가 필요한지 계획하고 → 얼마나 준비됐는지 확인하고 → 실제로 어디에 썼는지 연결하고 → 다음 여행에 재사용`하도록 돕는다.

## 2. 문제 정의

| Pain | 현재 문제 | 해결 방향 |
|---|---|---|
| 예산 설정 | 항공·숙박·식비 등의 정보를 따로 찾아 총액과 인당 금액을 감으로 결정한다 | 조건 기반 예상 여행비와 카테고리 예산 제공 |
| 자금 준비 | 통장 잔액은 보여도 무엇까지 준비됐는지 알기 어렵다 | 목표금액·준비율·부족금액·가상 여행 금고 제공 |
| 실제 소비 연결 | 실제 거래와 처음 세운 예산이 분리되어 있다 | 거래를 예산 카테고리와 계획 항목의 실제값으로 연결 |
| 데이터 재사용 | 여행이 끝나면 다음 여행에서 다시 처음부터 계산한다 | 결산·여행 유형·다음 여행 개인화 제공 |

## 3. 핵심 사용자

### Primary — 김지수 / 29세 / 직장인 / 여행 총무형

친구 3~4명과 정기적으로 여행하며 가격 검색, 엑셀 정리, 인당 회비 결정, 입금 확인, 여행 후 정산을 담당한다.

**Pain**

- 회비 금액의 근거가 부족하고 부족하면 다시 걷어야 한다.
- 현재 자금으로 무엇까지 준비됐는지 파악하기 어렵다.
- 여행 후 초과 지출 원인을 정리하지 않고 다음 여행에서 다시 계산한다.

**Needs**

- 전체 예상경비와 인당 목표금액
- 항목별 준비 상태
- 선택형 멤버 납부 현황
- 예상 vs 실제 결산
- 과거 소비 기반 다음 여행 추천

### Secondary Persona

| 유형 | 핵심 상황 | 주요 Needs |
|---|---|---|
| 예산 상한형 | 사용 가능한 예산을 먼저 정함 | 입력 예산과 추천 예산 비교, 부족/여유 확인 |
| 첫 해외여행형 | 비용 항목과 적정 금액 자체를 모름 | 추천 총액, 필수 카테고리, 기본 팁 |
| 목적형 여행 리더 | 다이빙·공연·트레킹 등 특수비용이 있는 다인원 여행 운영 | 목적별 계획 항목, 인당 금액, 반복 여행 데이터 |

## 4. 핵심 가치

1. **근거 있는 예산:** 여행지·일정·인원·스타일을 바탕으로 예상비를 제공한다.
2. **선택 가능한 자금 관리:** 기존/신규 계좌, 직접 입력, 0원 시작을 지원한다.
3. **준비 상태 가시화:** 현재 자금이 여행 계획의 어느 항목까지 준비됐는지 보여준다.
4. **예산 중심의 실제값 연결:** 거래내역은 예산 계획을 채우는 실제값이다.
5. **재미있는 여행 결과:** 여행 종료 후 예산과 지출을 바탕으로 대표 유형과 여러 특성을 보여준다.
6. **반복할수록 나아지는 추천:** 첫 여행부터 개인화에 사용하고 누적 데이터로 근거를 확장한다.

## 5. 서비스 중심축

```text
여행 생성
→ 여행 예산 계획
→ 여행자금 준비
→ 실제 소비
→ 예산과 실제 비교
→ 여행 결산
→ 여행 유형 결과
→ 개인/모임 데이터 축적
→ 다음 여행 개인화
```

UI는 여행 중심으로 제공하고 데이터는 개인 또는 모임에 누적한다. 개인 여행은 사용자 화면에서 `개인`으로 표현하며 내부적으로 본인 1명인 소유 단위로 처리할 수 있다.

## 7. 핵심 정책

### 7.1 여행 생성과 상시 화면

- 생성은 `누구와 → 기본정보 → 예산·자금 설정`의 3단계 1회성 흐름이다.
- 생성 후 핵심 상시 화면은 `2-2 여행 준비 홈`이다.
- 이후 수정은 생성 흐름 재진입이 아니라 준비 홈의 설정·바텀시트에서 처리한다.

### 7.2 금융 연결

- 금융계좌 연결은 필수가 아니다.
- 실서비스는 실제 금융데이터 연결을 목표로 하고 MVP는 Mock 계좌·거래 데이터를 사용한다.
- 수기에서 계좌로 전환하면 두 금액을 합산하지 않는다.
- 경고와 명시적 확인 후 현재 여행자금을 연결 계좌 잔액으로 대체한다.

### 7.3 예산과 거래

- 예산 계획이 서비스의 중심 데이터다.
- 거래는 예산 카테고리에 매핑되어 실제 사용금액을 갱신한다.
- 카테고리 내부 목록은 추천 관광지가 아니라 이번 여행에서 돈을 쓸 세부 계획 항목이다.
- 핵심 거래 입력과 기본 결산은 유료 횟수 제한을 두지 않는다.

### 7.4 여행 유형 결과

- 여행 1회 결산부터 유형을 산출한다.
- `대표 유형 1개 + 복수 특성/보조 유형`을 재미있는 이미지와 함께 보여준다.
- 근거는 목표·실제 총액, 많이 쓴 항목, 초과/절약 항목을 간략히 제공한다.
- 상세한 분석은 여행 결산으로 분리한다.

## 8. 비즈니스 모델

| BM | 구조 | MVP |
|---|---|---|
| 여행자보험 제휴 | 예상 보험 예산 → 제휴 보험사 실제 보험료 확인 → 유입/견적/가입 성과 수수료 검토 | 예상비와 외부 이동 UX |
| 유료 팁 마켓 | 무료 기본 팁 → 개별 유료 팁 구매 → 여행 후 팁 작성·판매 → 플랫폼 수수료 | 탐색·상세·구매/판매 흐름 |
| Premium 분석 후보 | 상세 그래프, 장기 모임 트렌드, 고급 개인화 | 범위 미확정, 구현 기준 아님 |

보험 상품 비교·적극 추천 및 개인정보 직접 전달은 규제 검토 전 범위에서 제외한다.

## 9. 실서비스와 MVP

| 영역 | 실서비스 | MVP |
|---|---|---|
| 금융 | 실제 계좌 잔액·입출금 연결 | Mock 계좌·거래 + 직접 입력 |
| 예상예산 | 외부 가격·과거 소비 기반 | 규칙·샘플 데이터 기반 |
| 거래 분류 | 자동 분류 + 사용자 수정 | Mock 자동 분류 + 수정 |
| 유형 | 결산 데이터 기반 이미지 결과 | 사전 정의 유형·규칙 기반 결과 |
| 보험 | 제휴 추적 | 제휴 이동 시뮬레이션 |
| 유료 팁 | 결제·정산 포함 | 결제/정산 Mock 또는 범위 제한 |
