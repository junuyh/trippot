## 1. 표기 기준

- `Must`: MVP 핵심 흐름 구현에 필수
- `Should`: 핵심 가치를 강화하며 가능하면 MVP 포함
- `Could`: 후속 확장
- `Future`: 이번 범위 밖. 스키마·구조로 막지는 않는다
- **구현 상태**: `구현` = 코드가 있고 진입 경로가 있다 / `부분` = 일부만 / `미구현` = 코드 없음 또는 placeholder
- 화면 ID는 `04_화면목록_v4.md`를 참조한다.
- **신설 REQ 의 우선순위 기준**: 정책 문서(`10`~`16`)로 팀이 확정한 것 = `Must`, 코드만 먼저 간 것(코드 선행) = `Should`, 미구현·미결정 = `Future` 또는 `[검토 필요]`. 이 문서가 새로 정한 우선순위는 없다.

> **🔁 변경 (v1 → v2)**
> - **이전**: Must / Should / Could 3단계, 화면 ID 는 `04_화면목록_v1.md` 참조
> - **문제정의**: 구현이 끝났는데 문서에 없는 기능과, 문서에 있는데 코드가 없는 기능이 같은 표에 섞여 "무엇이 지금 앱인가" 를 읽을 수 없었다
> - **의사결정**: `Future` 와 **구현 상태 열**을 추가한다 · 2026-09-18 · 18 §13
> - **상태**: 확정

## 5. 핵심 수용 기준

### AC-01 여행 생성

- 계좌를 연결하지 않아도 직접 입력 또는 0원으로 여행 생성을 완료한다.
- 추천 예산이 먼저 나오고, 직접 입력으로 전환해도 카테고리별 금액을 확인한 뒤 목표 예산을 확정한다.
- 완료 후 생성된 여행의 준비 홈으로 이동한다.

> **🔁 변경 AC-01 (v1 → v2)**
> - **이전**: "두 예산 설정 경로 모두 예상비 비교 후 목표 예산을 확정한다"
> - **문제정의**: 방식 선택 2택 화면이 없어져 "두 경로" 라는 표현이 화면과 맞지 않는다(REQ-BUDGET-001)
> - **의사결정**: 추천 기본값 → 직접 입력 전환 구조로 문구만 고친다. 확정 행동이 사용자에게 있다는 기준은 그대로 · 18 §2-12
> - **상태**: 확정

### AC-02 예산·거래 연결

- 거래의 카테고리를 설정하면 해당 예산의 실제 사용금액이 갱신된다.
- 갱신 결과가 예산 상세, 준비 홈 요약, 결산에서 일치한다.

### AC-03 수기→계좌 전환

- 확인 전에는 기존 수기 상태가 유지된다.
- 확인 후 현재 자금은 계좌 잔액으로 대체되며 합산되지 않는다.
- 전환 후 누적 모금액에 수기 입금 거래가 이중으로 잡히지 않는다. (v2 추가 · REQ-FUND-003)

### AC-04 여행 유형

- 결산 확정 후 대표 유형과 하나 이상의 보조 특성을 보여준다. — 보조 특성 표시는 **[검토 필요]** (REQ-TYPE-001)
- 최소 한 개의 예산·지출 근거를 함께 보여준다.
- 상세 결산으로 이동할 수 있다.

### AC-05 초대 · 참여 (v2 신설)

- ACTIVE 멤버가 초대하기를 누르면 같은 여행에서 7일 안에는 항상 **같은 링크**가 나온다.
- 수신자는 로그인 여부와 관계없이 링크로 여행 요약(초대한 사람 · 여행지 · 날짜)만 본다. 금액 · 멤버는 수락 전에 보이지 않는다.
- 여행장이 수락하면 요청자가 `trip_members` ACTIVE 가 되고, 개인 여행이었다면 같은 처리 안에서 새 모임이 만들어져 여행이 그 모임으로 옮겨진다. 실패하면 아무것도 바뀌지 않는다.
- 인원이 찼을 때 수락은 `HEADCOUNT_REACHED` 로 막히고, 인원을 늘려 저장한 뒤에는 수락된다.
- 수락 · 거절 · 참여 의사 도착이 각각 알림센터에 한 건씩 남고 안 읽음 점이 켜진다.

### AC-06 결산 (v2 신설)

- 종료일 다음 날 여행 홈에 들어가면 상태가 `ENDED` 가 되고 결산 유도가 뜬다. 사용자가 확정하기 전에는 `SETTLED` 가 되지 않는다.
- 확정 후 예산을 고쳐도 결산 화면의 카테고리별 값은 확정 시점 그대로다.
- 결산 확정 직후 여행 유형이 한 번 생성되고, 종료 홈에서 유형 · 정산 카드 · 명세서를 볼 수 있다.
- 정산 카드(이미지)와 명세서(PDF)는 미리보기를 거친 뒤 공유된다.
- 결산이 만들어졌는데 상태 갱신이 실패한 "반쪽 상태" 가 남지 않는다. — **[검토 필요]** (NFR-008 이 RPC 로 묶이기 전까지는 수동 롤백)
