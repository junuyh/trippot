# TripPot 정보구조 v1

## 0. 이 문서를 읽는 법

이 문서는 **서비스 전체 구조를 한눈에 보기 위한 트리**다.

- **화면 ID와 라우트는 `04_화면목록_v3.md` 가 기준이다.** 이 문서의 번호(1-1, 2-2 등)는 구조 이해용 참조 번호이며 코드에 사용하지 않는다.
- 트리의 하위 항목이 반드시 별도 화면인 것은 아니다. 한 화면 안의 섹션인 경우가 많다. 실제 화면 단위는 화면목록을 따른다.
- 화면 흐름과 분기 조건은 `02_유저플로우_v1.md` 가 기준이다.
- 기능 우선순위는 `03_요구사항정의서_v1.md` 가 기준이다.

## 2. 여행

서비스의 핵심 루프다. 담당: 리더

### 2-1. 여행 생성

> 화면: `TRIP-01` `TRIP-02` `TRIP-03` · `/trips/new/*` · MVP

생성은 최초 1회성 3단계 흐름이다. 생성 이후 수정은 이 흐름을 다시 타지 않고 2-2에서 처리한다.

```
2-1. 여행 생성
├─ STEP 1. 누구와 가나요?           TRIP-01
│  ├─ 개인
│  ├─ 기존 모임
│  │  └─ 과거 데이터가 있으면 인사이트 반영/제외 선택
│  └─ 새 모임
│     └─ 모임명 · 멤버 구성
│
├─ STEP 2. 여행 기본정보             TRIP-02
│  ├─ 여행지
│  ├─ 일정
│  ├─ 인원
│  └─ 여행 스타일
│
└─ STEP 3. 여행 예산·자금 설정        TRIP-03
   ├─ 예산 설정 방식
   │  ├─ 추천받고 정하기
   │  └─ 정해둔 예산 입력
   │     └─ 두 경로 모두 예상 여행비 비교로 수렴
   ├─ 카테고리 수정 → 목표 여행비 확정
   └─ 현재 여행자금 등록
      ├─ 기존 계좌
      ├─ 새 계좌
      ├─ 직접 입력
      └─ 0원 시작
```

> **MVP 범위:** 해외여행만 지원한다. 국내여행은 Future. (`CLAUDE.md` 3장)

### 2-3. 예산 상세

> 화면: `BUDGET-01` `BUDGET-02` · `/trips/[tripId]/budget` · MVP

**서비스의 중심 데이터 화면이다.** 거래내역이 아니라 예산 계획을 먼저 보여준다.

```
2-3. 예산 상세                              BUDGET-01
├─ 전체 예산 현황
│  ├─ 목표 여행비
│  ├─ 현재 준비된 여행자금
│  ├─ 실제 사용금액
│  ├─ 남은 예산
│  └─ 예상 대비 사용률
│
├─ 카테고리별 예산 (8개)
│  항공 · 숙박 · 식비 · 교통 · 관광/액티비티 · 쇼핑 · 여행자보험 · 예비비
│
└─ 카테고리 상세                            BUDGET-02
   ├─ 설정 예산 / 준비 금액 / 실제 사용 / 남은 예산
   ├─ 준비율 / 사용률
   ├─ 세부 계획 항목
   │  ├─ 항목명 · 예상금액 · 실제금액 · 상태
   │  └─ 추가 / 수정 / 삭제
   ├─ 해당 카테고리 실제 지출
   │  └─ 거래 선택 → 2-4 거래 상세
   ├─ 예산 인사이트
   └─ 관련 여행 팁                          [고도화]
      ├─ 무료 팁 노출
      └─ 내 예산에 반영
```

> 세부 계획 항목은 관광지 추천 목록이 아니다. **이번 여행에서 돈을 쓸 계획 항목**이다.

> 화면: `FUND-01` `FUND-02` `FUND-03` · `/trips/[tripId]/funds` · **고도화**

```
2-4. 여행자금 / 입출금 관리
├─ 현재 여행자금 (잔액 / 목표 / 부족금액)     FUND-01
├─ 자금 관리 방식 (계좌 연결 / 직접 입력)
├─ 입출금 전체 내역 (전체 / 입금 / 출금)
├─ 거래 상세                                 FUND-03
│  ├─ 거래일 · 거래명 · 금액 · 입출금 구분
│  ├─ 예산 카테고리
│  └─ 카테고리 수정
├─ 계좌 연결 / 전환                          FUND-02

> **정책:** 직접입력 금액과 연결계좌 잔액을 합산하지 않는다. 확인 후 계좌 잔액으로 대체한다.

### 2-5. 여행 유형 결과

> 화면: `TYPE-01` · `/trips/[tripId]/type-result` · **고도화**
> **[미확정]** 유형 목록과 산출 방식(규칙 기반 / AI 활용)이 아직 정해지지 않았다.

결산 데이터를 공유하고 싶은 결과로 재해석하는 화면이다. 상세 분석은 2-6이 담당한다.

```
2-5. 여행 유형 결과
├─ 결과 인트로
├─ 대표 유형
│  ├─ 유형 일러스트
│  ├─ 유형명
│  └─ 한 줄 설명
├─ 세부 여행 유형                    [미확정 — 아래는 예시]
│  미식형 · 숙소 중시형 · 체험/액티비티형 ·
│  쇼핑 중심형 · 알뜰 절약형 · 교통 효율형
├─ 여행 특성 키워드                  [미확정 — 아래는 예시]
│  "먹는 데 아끼지 않음" · "숙소보다 체험 우선" ·
│  "계획보다 즉흥 소비" · "예산 방어 성공"
├─ 유형 산출 근거 요약
│  ├─ 목표 여행비 / 실제 여행비
│  ├─ 가장 많이 지출한 카테고리
│  ├─ 예상보다 많이 쓴 카테고리
│  ├─ 예상보다 절약한 카테고리
│  └─ 카테고리별 대표 수치
├─ 데이터 기준 안내
├─ [결과 이미지 저장]
├─ [친구에게 공유]
├─ [상세 결산 보기] → 2-6
└─ [이 결과로 다음 여행 만들기] → 2-1
```

> **미확정 사항**
> - 유형 목록: `lib/constants/status.ts` 의 `SPENDING_PROFILE_TYPE` 6개는 **임시값**이다.
>   이 문서의 예시(교통 효율형 포함)와도 일치하지 않는다.
> - 산출 방식: 예산 편차 기반 규칙 / AI 활용 중 미정.
> - `03_요구사항정의서` `REQ-TYPE-001` 의 "여행 1회 결산부터 대표 유형 + 복수 특성" 구조만 확정.

### 2-6. 여행 결산

> 화면: `SETTLE-01` · `/trips/[tripId]/settlement` · MVP

```
2-6. 여행 결산
├─ 목표 여행비 vs 실제 여행비

## 6. 핵심 흐름

IA 전체에서 가장 강하게 읽혀야 하는 축이다.

```
여행 생성 (2-1)
↓
여행 예산 계획 (2-3)
↓
여행자금 준비 (2-2 · 2-4)
↓
실제 소비 (2-4)
↓
예상 vs 실제 비교 (2-3)
↓
여행 결산 (2-6)
↓
여행 유형 결과 (2-5)
↓
개인 / 모임 데이터 누적
↓
다음 여행 개인화 (2-1)
```

보험 · 팁 · 커뮤니티는 이 축을 보조하는 Branch다. 핵심 흐름보다 시각적으로 강해지지 않게 한다.
