# 15. 회원탈퇴 정책 v2 (팀 확정 · 2026-09-23)

| | |
|---|---|
| 버전 | v2 — 30일 경계·타인 노출·협업 정합성·최종 정리를 끝까지 규정한다 |
| 이전 | [`15_회원탈퇴정책_v1.md`](15_회원탈퇴정책_v1.md) (2026-09-17 · 보존) |
| 변경 사유 | v1 은 상태 전이와 서버 함수까지만 정했다. 실제 구현 audit(2026-09-22)에서 ① 30일 경계가 서버에 없고 ② 유예 계정이 취소 투표 정족수를 교착시키고 ③ 최종 탈퇴자가 `이름 없음` 으로 보이고 ④ 유예 계정에 새 협업 관계를 맺을 수 있고 ⑤ 개인성 데이터 정리 규정이 없다는 것이 드러났다. v2 는 그 다섯 가지를 정책으로 확정한다 |
| 표기 | **[확정]** 정책 · **[구현]** 현재 코드 · **[GAP]** 아직 없는 것 — 셋을 섞지 않는다 |

여행 취소(72시간) 도메인은 다른 담당 영역이며 이 문서는 그 정책을 바꾸지 않는다.

---

## 1. 목적
탈퇴 의사를 존중하되 **30일 안에는 되돌릴 수 있게** 하고, 그 사이에도 다른 사람의 공동 기록과 진행 중인 협업이 깨지지 않게 한다. 탈퇴 사실은 개인정보이므로 다른 사용자에게 알리지 않는다.

## 2. 상태 정의 [확정]
새 enum 을 만들지 않는다. `users` 의 두 시각으로만 가른다.

| 상태 | 판정 |
|---|---|
| ACTIVE | `withdrawal_requested_at is null` and `deleted_at is null` |
| PENDING_WITHDRAWAL | `withdrawal_requested_at is not null` and `deleted_at is null` |
| WITHDRAWN | `deleted_at is not null` (tombstone · 행은 보존) |

`is_account_active()` = ACTIVE 만 true.

## 3. 탈퇴 요청 조건 [확정]
- 본인만. 멱등(이미 신청했으면 같은 예정일을 돌려준다)
- **다른 ACTIVE 멤버가 있는 PLANNING · TRAVELING 여행의 여행장은 위임 먼저** → `LEADER_MUST_DELEGATE`
- 혼자뿐인 여행 · 끝난 여행(ENDED · SETTLED)은 막지 않는다

## 4. 30일 유예기간 [확정]
예정일 = `withdrawal_requested_at + 30 days`. 유예 동안 **일반 서비스 이용은 전면 차단**하고 탈퇴 취소만 열어 둔다.

## 5. 30일 deadline · finalize 전 "처리 중" 구간 [확정]
```
now() <  신청 + 30일   → 탈퇴 취소 가능
now() >= 신청 + 30일   → 탈퇴 취소 불가 (cron 실행 여부와 무관)
```
cron 은 하루 1회라 "30일은 지났는데 아직 WITHDRAWN 은 아닌" 구간이 생긴다. 그 구간에서는
- 일반 서비스 이용 계속 차단 · 탈퇴 취소 CTA **미노출** · `탈퇴 처리 중` 안내 · 로그아웃 가능 · 다음 finalize 에서 WITHDRAWN

**서버가 같은 경계를 판정한다.** UI 에서만 숨기지 않는다 → `WITHDRAWAL_WINDOW_CLOSED` (errcode 22023).

## 6. 탈퇴 취소 [확정]
사용자의 **명시적 버튼**으로만. 로그인만으로 자동 복구하지 않는다. 취소하면 같은 `user id` 로 ACTIVE 복귀하고 모임·여행·공유 관계가 그대로 살아난다(아무것도 바꾼 적이 없으므로).

## 7. 본인 UX [확정]
로그인은 되지만 `/withdrawal-pending` 외 어떤 화면도 열지 않는다.

| 구간 | 화면 |
|---|---|
| 30일 이전 | `이 계정은 탈퇴가 진행 중이에요` / `탈퇴 예정일: YYYY.MM.DD` / `예정일까지는 탈퇴를 취소할 수 있어요.` + **[탈퇴 취소]** + 로그아웃 |
| 30일 이후 · finalize 전 | `탈퇴 처리 중` 안내 · **[탈퇴 취소] 없음** + 로그아웃 |

## 8. 타인 노출 정책 [확정]
다른 사용자에게 **절대** 보이지 않는 것: `탈퇴 대기 중` · `탈퇴 예정` · 신청 시각 · 예정일 · 탈퇴 사유.
`withdrawal_requested_at` 은 어떤 view · RPC 로도 내보내지 않는다.

## 9. "현재 활동 불가" 정책 [확정]
행동 가능 여부가 필요한 협업 화면에서만 중립 라벨 **`현재 활동 불가`** 를 쓴다. 이는 탈퇴를 뜻하지 않는 **파생 협업 상태**이며, 구현은 boolean 하나(`is_collaboration_available`)로 한다.

표시하는 곳: 진행 중 모임 멤버 · 진행 중 여행 멤버 · 진행 중 여행의 여행장 · 여행 취소 투표 참여자.
표시하지 않는 곳: 과거 납부 · 과거 지출 · 완료 정산 · 과거 여행 기록(기존 이름 유지) · **커뮤니티(익명 유지)**.

## 10. 멤버십 · headcount [확정]
PENDING 이 되어도 `trip_members` · `group_members` 를 LEFT 로 만들지 않는다. **자리(headcount)는 유지**한다 — 30일 안에 돌아올 수 있기 때문이다. 정원 4에 ACTIVE+PENDING 이 4면 5번째를 받지 않는다.

## 11. 의사결정 quorum [확정]
**지금 행동할 수 없는 계정은 정족수의 분모에서 뺀다.** 여행 취소 투표(`_trip_cancel_tally.target_count`)가 그 대상이다. 자리는 유지하고 분모만 뺀다 — 둘을 혼동하지 않는다.

## 12. 초대 · 참여 · 위임 [확정]
기존 공동 관계는 유지하되 **새 공동 관계는 만들지 않는다.**
PENDING 사용자를 대상으로: 새 초대 ❌ · 새 여행 자동 합류 ❌ · 여행장 위임 ❌ · 참여 요청 수락으로 신규 멤버화 ❌ · 새 의사결정 대상 ❌ · 새 공동 비용 participant ❌.
탈퇴 신청 순간 **본인의 PENDING 참여 의사는 CANCELED** 로 정리한다. 돌아온 뒤에는 새 링크로 다시 보낸다.

## 13. 여행장 예외 [확정]
혼자만 ACTIVE 인 여행의 여행장은 신청할 수 있다. 유예 동안 그 여행은 유지되지만 신규 합류·수락·위임이 없다. 살아 있는 초대 링크로 들어온 사람에게는 탈퇴 사실을 알리지 않고 기존 invite unavailable 패턴으로만 안내한다. 탈퇴를 취소하면 정상 복귀한다.

## 14. 납부 · 지출 · 정산 [확정]
신청 이전 기록과 책임은 **그대로**다. PENDING 전환을 이유로 공동 금액을 재계산하지 않는다. 다만 이후 새로운 비용 participant 지정 · 새 정산 관계 생성은 하지 않는다.

## 15. 최종 탈퇴 (WITHDRAWN) [확정]
30일 경과 후 cron/Edge 가 처리한다.
`trip_members → LEFT` · `group_members → LEFT` · 남은 PENDING 참여 요청 → `CANCELED` · 본인 notifications 삭제 · `users` 식별정보 비식별화(`name='탈퇴한 회원'`, english_name · 사진 · provider · 설정 비움) · `deleted_at` · `auth.users` 삭제.
같은 카카오/구글/이메일로 다시 가입해도 **새 auth.uid = 새 사용자**다. 과거 계정과 자동으로 잇지 않는다.

## 16. 공유 여행 보존 [확정]
**공유 여행** = 탈퇴자 외 다른 사용자가 **한 번이라도 실제 참여자였던** 여행. `trip_members` 는 나가도 LEFT 로 남으므로 그 이력으로 판정한다. 공유 여행은 삭제하지 않고 탈퇴자만 `탈퇴한 회원` 으로 익명화한다.

## 17. 개인성 여행 삭제 [확정]
**개인성 여행** = 탈퇴자 외 다른 사용자가 한 번도 실제 참여자였던 적이 없는 여행. 다음은 참여로 보지 않는다 — 초대 링크 생성 · 초대 열람 · PENDING 참여 의사 · 거절/취소된 참여 요청.
최종 탈퇴 후 서비스 제공 목적이 사라지므로 그 여행과 **그 사용자만을 위한 종속 데이터**를 삭제한다. 다음 표 중 하나라도 다른 사용자의 행이 있으면 삭제하지 않는다: `trip_members` · `contributions` · `community_posts` · `insurance_referrals` · `notifications` · `trip_invites` · `trip_cancel_requests`.
MVP 의 mock · 직접입력 금액은 법정 보존 대상으로 보지 않는다. 별도 보존 의무가 확인되면 그 데이터는 예외로 둔다.

## 18. 그룹 · container 처리 [확정]
개인성 여행을 지운 뒤, 그 모임에 **여행이 하나도 남지 않았고** 탈퇴자 외 멤버가 없었던 경우에만 모임을 정리한다. `trips.group_id` 는 `on delete cascade` 이므로 남은 여행이 있으면 **절대** 모임을 지우지 않는다.

## 19. 과거 기록의 `탈퇴한 회원` [확정]
공유 기록(여행 이력 · 납부 · 지출 · 정산 · 과거 여행장/멤버)에서 탈퇴자는 **`탈퇴한 회원`** 으로 통일한다.
금지: `이름 없음` · 원래 이름 · 프로필 사진 · 프로필로 이동.
현재 멤버 목록 · 여행장 후보 · 초대 대상 · 협업 대상에서는 제외된다(멤버십이 LEFT 이므로).

## 20. 커뮤니티 익명 정책 [확정 · 변경 없음]
모든 글과 댓글은 익명이다. ACTIVE · PENDING · WITHDRAWN 어떤 상태도 커뮤니티 UI 에 드러내지 않는다.

## 21. 알림 익명화 · 삭제 [확정]
- 본인에게 온 알림: finalize 에서 삭제
- 다른 사용자 알림함에 남은 **이 사람이 actor 인 알림**: 구조적으로 식별 가능한 것(`data->>'actorUserId'`)만 삭제
- **이름 문자열을 전체 검색·치환하지 않는다.** actorUserId 가 없는 옛 알림은 손대지 않고 GAP 으로 남긴다
- 앞으로 만드는 알림은 가능한 한 actor 를 구조화해 남긴다

## 22. 프로필 이미지 Storage 삭제 [확정]
DB 의 `profile_image_url` 을 비우는 것으로 끝내지 않는다. **실제 Storage object 를 지운다.** Edge Function `withdrawal-cleanup` 이 `profile-images/{uid}/*` 를 Storage API 로 지우고 `finalize_withdrawals()` 를 이어서 부른다(멱등).

## 23. 재가입 정책 [확정]
탈퇴 후 같은 인증수단으로 다시 가입하면 새 사용자다. 과거 기록·여행·모임을 자동으로 잇지 않는다.

## 24. 보안 · 개인정보 원칙 [확정]
- `public.users` 는 **본인 행만** SELECT (`users_select_self`)
- 타인 프로필은 최소 공개 view 로만: `id` · `name` · `profile_image_url` · `is_collaboration_available`
- **시각(timestamp)은 어떤 경우에도 공개하지 않는다**
- 탈퇴자의 원래 이름·사진·provider 식별자는 다시 공개하지 않는다
- finalize 는 cron/service_role 전용, 앱에는 `service_role` 을 두지 않는다

## 25. 예외 · 실패 처리 [확정]
- `cancel_withdrawal` 실패 코드: `AUTH_REQUIRED` · `NOT_FOUND` · `ALREADY_WITHDRAWN` · `WITHDRAWAL_WINDOW_CLOSED`
- 위임/수락 거부 코드: `TARGET_NOT_ACTIVE` · `REQUESTER_NOT_ACTIVE`
- Storage 삭제 실패는 다음 실행에서 다시 시도한다(멱등). DB 처리는 막지 않는다
- `auth.users` 삭제 실패는 삼키고 tombstone 으로 세션을 끊는다
