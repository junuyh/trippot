## 1. 개인 여행(PERSONAL)은 DB 에 모임이 없다

```
trips.owner_type     = 'PERSONAL'
trips.owner_user_id  = 본인
trips.group_id       = null

groups         행 없음
group_members  행 없음
trip_members   본인 1행 (ACTIVE)
```

`trips_owner_shape` CHECK (`init_schema.sql:114`) 가 이 형태를 강제한다.
**개인 여행마다 가짜 groups 행을 만들지 않는다.** 데이터 모델은 이대로 둔다.

### 1-1. headcount 는 개인/모임 판정과 무관하다

`trips.headcount` 는 **예산 계산용 예정 인원**이다 (`10_여행초대정책_v2.md` §10).

```
headcount = 4 · ACTIVE trip_members = 1 · owner_type = PERSONAL   → 여전히 개인 여행
```

headcount 를 1 → 4 로 바꿔도 PERSONAL → GROUP 으로 **자동 전환하지 않는다.**
"4명 예정 · 지금은 나 혼자" 는 정상 상태다.

### 1-2. 개인 여행의 이름

"개인 여행" 은 **시스템 표시명**이다. `groups.name` 이 아니다.
그래서 개인 여행에는 **모임 이름 수정이 없다.** (§3)

## 2. GROUP-01 모임 탭에는 개인 여행도 보인다

### 2-1. 정책

사용자가 참여 중인 **실제 모임** + 본인이 소유한 **유효한 개인 여행** 을 **같은 목록**에서 본다.

```
UX      실제 모임 카드 N장 + 개인 여행 카드 **최대 1장**  (같은 카드 디자인 · 1열)
DB      개인 여행은 여전히 모임이 아니다
```

**개인 여행이 몇 개든 '개인 여행' 카드는 하나다.** 여행마다 카드를 만들지 않는다.
(2026-09-12 확정 — 1차 구현의 "여행 1건 = 카드 1장" 은 폐기)

```
개인 여행: 니스 · 후쿠오카 · 뉴욕   →   GROUP-01: [개인 여행] 카드 1장
```

둘을 섞어 보여주되 **DB 에서 위조하지 않는다.** display model 에서만 합친다.

### 2-2. 구현 기준 (2026-09-12)

| 항목 | 값 |
|---|---|
| 개인 여행 조회 | `owner_type = PERSONAL` · `owner_user_id = 나` · `status ∉ (DELETED, CANCELED)` — `getTrips` 와 같은 필터. 새 상태 규칙을 만들지 않는다 (`lib/supabase/queries/trips.ts` `getMyPersonalTrips`) |
| 카드 1장 | = **내 개인 여행 전부** (collection) |
| display model | `GroupTravelCardData` 를 `kind: 'GROUP' \| 'PERSONAL'` 로 나눈다. PERSONAL 은 **`groupId` · `memberCount` · `tripId` 가 없다** — 특정 여행 하나를 가리키지 않는다 (`components/groups/types.ts`) |
| 카드 이름 | `개인 여행` (시스템 표시명) |
| 인원 칸 | 실제 모임은 `N명`, 개인 여행은 `개인` |
| 진행 중 줄 | 개인 여행 중 PLANNING · TRAVELING, `start_date` 최신순 — `getGroupTrips` 와 같은 규칙. 2건 넘으면 기존 "외 N건" |
| 지난 여행 수 | 개인 여행 중 ENDED · SETTLED 수 |
| 정렬 키 — 최근 여행순 | 개인 여행 중 **이미 시작한 것의 가장 늦은 `start_date`** (`latestStartedTripDate`, 실제 모임과 같은 함수) |
| 정렬 키 — 생성순 | 개인 여행 중 **가장 최근 `trips.created_at`** — 모임이 없으니 여행 것을 쓴다. `Date.now()` 나 가짜 값을 만들지 않는다 |
| 편집 모드(숨기기) | **실제 모임만** 선택 가능. 숨김 설정이 `group_id` 기준(`user_group_list_preferences`)이라 개인 여행은 대상이 없다 |
| Empty State | **실제 모임 0 · 개인 여행 0** 일 때만 "아직 참여 중인 모임이 없어요" |

### 2-3. 개인 여행 카드를 누르면 — 개인 여행 상세 `/groups/personal`

개인 여행에는 `groupId` 가 없어 GROUP-02(`/groups/:groupId`)로 갈 수 없다. **가짜 id 를 만들지 않는다.**
대신 **개인 여행 상세** 로 간다. 내 개인 여행 전부를 상태별로 본다.

| 항목 | 값 |
|---|---|
| route | `/groups/personal` — `app/groups/personal.tsx`. 정적 라우트라 `[groupId]` 보다 우선 (`new.tsx` 와 같은 선례) |
| 헤더 | `개인 여행` |
| 탭 | **준비 중 · 여행 중 · 지난 여행 · 취소됨** (4개). **'나간 여행' 없음** — 개인 여행은 내가 주인인 독립 여행이라 "나간다" 는 구조가 아니다. 모임으로 전환된 뒤 나가면 실제 모임의 '나간 여행' 에서 다룬다 |
| 컴포넌트 | `MyTripListView` (MY-02 것 그대로, `tabs` 만 4개) · `MyTripCard`. GROUP-02 를 복사하지 않는다 |
| 없는 것 | 모임 이름 수정 · 멤버 · 모임원 관리 · 연결 계좌 묶음 · 모임 생성일 — 가짜로 만들지 않는다 |
| 카드 탭 | MY-02 와 같이 여행 준비 홈 `/trips/:tripId` |
| 조회 | `getMyPersonalTrips(userId)` + `getCanceledTrips(userId)` 에서 `owner_type = PERSONAL` 만 |

> 1차(2026-09-12 오전)의 "카드 = 여행 1건 → 여행 준비 홈" 은 폐기됐다.

## 3. 모임 이름 수정 — 실제 모임만

| 항목 | 값 |
|---|---|
| 대상 | `group_id` 가 있는 **실제 모임만.** 개인 여행에는 노출하지 않는다 |
| 진입 | GROUP-02 헤더 우측 연필(`pencil-outline`) → `GroupRenameModal` |
| 검증 | 공백 금지 · **20자** 이내 (`GroupRenameModal` `MAX_NAME_LENGTH`). 새 규칙을 만들지 않는다 |
| 저장 | `updateGroup(groupId, { name })` (`lib/supabase/queries/groups.ts`) |
| 반영 | 성공 시 서버가 돌려준 이름으로 헤더 즉시 갱신. GROUP-01 은 탭 복귀 시 다시 읽는다 |
| 권한 | **RLS 가 판단한다.** 기존 정책(`05_ERD` §6-2 · `updateGroup` 주석): groups 는 **소유자 또는 ACTIVE 멤버**. 앱에 별도 모임장 검사를 두지 않는다 — 두 곳에 규칙이 생기면 서로 어긋난다 |

**모임장 개념은 만들지 않는다.** (`10_여행초대정책_v2.md` §2)

`GroupMoreMenu`(이름 수정 · 대표 이미지 · 모임원 관리)는 뒤 두 기능이 아직 없어 **띄우지 않는다.** 파일은 남긴다.

## 4. 첫 외부인 승인 — PERSONAL → GROUP 전환 [후속 accept 구현 정책]

개인 여행에 **첫 외부인이 실제로 승인되는 순간** 모임이 필요하다.
이 전환은 **초대 accept 구현**(`10_여행초대정책_v2.md` §8 · §9-4)에서 한 트랜잭션으로 처리한다.
**GROUP UI 작업에서는 구현하지 않는다.** (2026-09-12)

```
PERSONAL trip 에 참가 요청 ACCEPT
  → 새 groups 행 생성
  → 기존 본인 + 신규 승인자를 group_members ACTIVE 로
  → trips.owner_type   PERSONAL → GROUP
  → trips.owner_user_id → null            (trips_owner_shape CHECK)
  → trips.group_id     → 새 group
  → 신규 사용자를 trip_members ACTIVE 로
  → trip_join_requests ACCEPTED
```

- **새 여행 row 를 만들지 않는다.** 기존 trip 이 그대로 모임 소속이 된다 (`10_v2` §9-4)
- 새 모임 이름은 **INV-05 를 accept 시점에 쓰는 방향**이 최신 우선안이다. 이름을 정하기 전까지 시스템 표시명을 어떻게 둘지는 accept 구현 때 정한다
- 여행 단위 데이터(`fund_sources` · `transactions` · 예산)는 trip 과 함께 그대로다. 이관 로직 없음

이 절이 곧 `10_여행초대정책_v2.md` §9-4 표의 **"모임 멤버 아님 + 기존 여행 없음"** 케이스가 개인 여행일 때의 구체 절차다. v2 를 고치지 않고 여기 적는다 (CLAUDE.md 1-1).

## 6. 모임 상세(GROUP-02) 여행 탭 — 5개 (2026-09-12)

| 탭 | 기준 | 카드 동작 |
|---|---|---|
| 준비 중 | `trips.status = PLANNING` | 참가자면 여행 홈 · 왼쪽 swipe 로 나가기 |
| 여행 중 | `TRAVELING` | 참가자면 여행 홈 |
| 지난 여행 | `ENDED` · `SETTLED` | 참가자면 여행 홈 |
| **취소됨** | `trips.status = CANCELED` (`getGroupCanceledTrips`) | MY-02 와 같이 여행 홈. **표시만** |
| **나간 여행** | `trip_members.status = LEFT` 이고 이 모임 소속 (`getLeftTrips` 에서 group_id 로 거름) | **이동하지 않는다.** 누르면 안내 모달 |

상태 이름·의미는 MY-02(`MY_TRIP_FILTER_TABS`)와 같다. 화면마다 다시 정의하지 않는다.
나갔는데 취소까지 된 여행은 MY 와 같이 **'나간 여행' 에만** 둔다.

### 6-1. 취소됨 — 담당 경계 ⚠️

이 문서와 GROUP 작업의 책임은 **"취소된 여행을 탭에 보여준다"** 까지다.

| 우리 담당 | 다른 담당 (취소 기능) |
|---|---|
| 취소됨 탭 · CANCELED 여행 카드 표시 | 취소 후 **72시간 되돌리기** |
| 금액 없이(`—`) 흐리게 그리기 (MY-02 와 동일) | `canceled_at` 기준 경과 시간 계산 |
| — | 복구 버튼 · CTA · `restoreTrip` |
| — | 72시간 이후 숨김·정리 |
| — | 취소 상태 전이 |

GROUP 쪽 코드는 `canceled_at` 을 읽지 않고 시간을 계산하지 않는다. 취소 기능이 develop 에 들어오면 그쪽의 공용 helper 를 **재사용만** 검토한다.

### 6-2. 나간 여행 카드

- 현재 ACTIVE 참가자가 아니다 → 여행 수정 불가 · 나가기 불가 · 여행 홈 진입 불가
- **눌러도 아무 일이 없는 카드를 두지 않는다.** 누르면 안내: `이미 나간 여행이에요` / `이 여행에서는 나간 상태라 여행 준비 화면을 열 수 없어요.` / `확인`
- swipe 나가기 없음 (참가자 조건에서 이미 빠진다)
