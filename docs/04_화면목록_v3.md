## 0. 이 문서를 읽는 법

- **담당자 컬럼은 화면의 고정 소유자**를 뜻한다. 담당 외 화면을 임의로 수정하지 않는다.
- **A는 담당자 컬럼에 없다.** A는 고정 소유 화면이 없고, **L이 인계를 선언한 화면**의
  디자인·디테일을 맡는다. 인계 시점부터 그 화면은 A 소유이며 L은 이후 수정하지 않는다.
  인계 기준은 **데이터 연결 + 로그 삽입 완료 시점**이다. 디자인이 덜 됐어도 넘긴다.
- **`[미확정] B 또는 C`** 는 담당 영역만 정해졌고 분담 방식이 정해지지 않은 화면이다.
  한 명이 전부 맡을 수도, 둘이 나눌 수도 있다. **작업 전에 사람에게 담당자를 먼저 확인한다.**

자세한 소유·인계 규칙은 `CLAUDE.md` 13장을 따른다.

## 1. 라우트 원칙

- 상세 리소스는 `:tripId`, `:groupId`, `:postId`, `:transactionId`, `:categoryId` 를 사용한다.
  (`CLAUDE.md` 6장 식별자 계약과 동일한 이름을 쓴다)
- 팝업·바텀시트는 별도 라우트가 아닌 화면 내부 상태로 처리한다.
- 담당자 미지정 화면은 임의 배정하지 않는다.
- **Expo Router 파일 경로를 병기한다.** 논리 라우트(`:param`)와 실제 파일 경로(`[param]`)는
  표기만 다르고 같은 것이다.
- **하단 탭 4개**(홈·모임·커뮤니티·마이페이지)는 `app/(tabs)/` route group 아래 둔다.
  `(tabs)` 는 **URL에 나타나지 않으므로** 논리 라우트는 `/`, `/groups`, `/community`, `/me` 그대로다.
  상세 화면은 `(tabs)` 밖에 두어 탭 위에 Stack으로 쌓이게 한다 — 탭바가 사라지고 뒤로가기가 생긴다.

## 5. 동일 Route의 상태 분기

`TRIP-HOME-01`과 `TRIP-HOME-02`는 같은 Route(`app/trips/[tripId]/index.tsx`)를 사용하며
`trip.status`로 UI를 분기한다. 두 화면 모두 L 담당이고 MVP다.

| 상태 | 값 | 핵심 CTA |
|---|---|---|
| 준비 중 | `PLANNING` | 예산·자금 관리, 여행 종료 |
| 여행 중 | `TRAVELING` | 거래 기록, 사용 현황 확인 |
| 종료/결산 전 | `ENDED` | 결산 완료 |
| 결산 완료 | `SETTLED` | 유형 결과, 팁 작성, 다시 만들기 |

상태 문자열은 `lib/constants/status.ts` 의 `TRIP_STATUS` 상수만 쓴다. 리터럴 금지. (`CLAUDE.md` 6장)

## 6. 팝업·바텀시트

별도 라우트를 만들지 않고 화면 내부 상태로 처리한다.

- 목표 여행비 간단 수정
- 현재 여행자금 수정
- 여행 기본정보 일부 수정
- 계획 항목 추가·수정·삭제 확인
- 거래 카테고리 변경
- 수기 데이터 초기화·대체 경고
- 계좌 연결 해제
- 여행/모임/게시글 삭제 확인
