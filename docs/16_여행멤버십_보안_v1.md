# 16. 여행 멤버십 · 권한 보안 v1 (2026-09-17 · migration `20260917000003_travel_membership_security.sql`)

`여행 초대 → 참여 요청 → 승인 → 참여 → 나가기 / 취소 / 여행장 위임` 을 하나의 권한 lifecycle 로 보고,
앱 UI 뿐 아니라 API 로 직접 불러도 같은 규칙이 지켜지도록 DB(RLS · GRANT · RPC)에서 강제한 내용이다.
정책 자체는 새로 만들지 않았다 — `10_v2` · `11_v1` · `12_v1` · `20260916000004` 의 확정 정책을 그대로 강제한다.

## 1. 지켜지는 정책 (변경 없음)

| 영역 | 정책 | 강제 지점 |
|---|---|---|
| 초대 링크 | ACTIVE 참여자만 생성 · 유효 링크(7일)가 있으면 **재사용** · 만료 후에만 새 token · 여러 수신자 사용 가능 | `get_or_create_trip_invite` (trip `FOR UPDATE` 잠금 → race 시 1개) · 취소/삭제 여행 `TRIP_NOT_OPEN` |
| 참여 | 링크만으로는 참여 아님 → PENDING 요청 → **여행장 승인** 후 ACTIVE | `request_trip_join` (본인 `auth.uid()` 만 · 만료/무효 링크 거부 · ALREADY_MEMBER · REJECTED · PENDING 멱등 · 취소/삭제 여행 거부) · `accept_trip_join_request` (현재 여행장만 · PENDING 만 · headcount · 한 트랜잭션에서 trip_members + group_members + 요청 상태) |
| 참여자 = 모임 멤버 | ACTIVE 참여자는 그 여행 모임의 ACTIVE 멤버 | 승인 RPC 가 group_members 를 같이 만든다(CASE A~D) |
| 나가기 | **PLANNING 여행에서만** · 참여자 본인만 · 여행장은 위임 후 · 마지막 1인은 불가 · 행 삭제 없이 `LEFT` · 모임 멤버십은 기본 유지(사용자가 고르면 같이 나감) | `leave_trip` · `delegate_and_leave` (`TRIP_NOT_LEAVABLE` — migration 20260917000004 · `NEEDS_DELEGATION` · `LAST_MEMBER`) |
| 여행장 위임 | 현재 여행장만 · 대상 = 그 여행 ACTIVE 참여자 · 탈퇴 대기/완료 계정 불가 | `delegate_trip_leader` · `delegate_and_leave`(한 트랜잭션) |
| 취소 | ACTIVE 참여자가 요청 → 전원 동의(CANCEL_PENDING) · 기록 삭제 없음 | `request_trip_cancel` · `cast_trip_cancel_vote` · `trips_guard_direct_update` 트리거(직접 UPDATE 로 status/leader 변경 불가) |
| 탈퇴 대기 | PENDING_WITHDRAWAL · WITHDRAWN 계정은 위 어떤 변경도 불가 | 14개 RPC 첫머리 `is_account_active()` → `ACCOUNT_NOT_ACTIVE` · RLS INSERT/UPDATE 정책 |

## 2. 이번에 막은 것 (audit 2026-09-17)

- **P0** `groups` · `group_members` 의 `dev_open_all` + anon 전권 GRANT 제거 → 멤버/owner 만 읽고, owner 만 만들고, 멤버가 이름 수정, 삭제는 생성 10분 내 롤백만. group_members 는 owner 만 INSERT(모임 만들기), UPDATE/DELETE 는 RPC 로만.
- **P0** `trip_members` INSERT 가 `can_access_trip` 만 보던 것 → `user_id = auth.uid()` 본인 행만(여행 생성 때). 남을 ACTIVE 로 넣는 길은 승인 RPC 뿐.
- **P1** `trip_invites` anon 전권 · authenticated DELETE GRANT 회수 (token 표는 RPC 로만).
- **P1** 취소/삭제된 여행에 초대 생성 · 참여 요청 차단, 탈퇴 대기 계정의 여행 RPC 차단, 탈퇴 대기 계정 여행장 지정 차단.
- helper `is_group_member(group_id)` (STABLE SECURITY DEFINER · search_path '') — group_members 정책 재귀 회피.

## 3. RPC 보안 상태

- 14개 mutating RPC 전부 `SECURITY DEFINER` · `auth.uid()` 기반 · 본인/여행장/ACTIVE 멤버 검증 · 상태 전이 검사 · `FOR UPDATE` 잠금(초대 생성 · 승인/거절) · anon/PUBLIC EXECUTE 없음 · authenticated 만.
- `search_path` 는 `public, pg_temp`(고정 스키마 + pg_temp 마지막) — `''` 로 바꾸려면 본문 전체 재작성이 필요해 이번엔 유지(P2). 새로 만든 helper 는 `''`.

## 4. 남은 것

- 초대 링크 랜딩(`resolve_trip_invite`)은 로그인 필요(`AUTH_REQUIRED`) — 현재 UX(로그인 후 `next` 복귀)와 일치, 변경 없음.
- `groups.owner_user_id` 를 멤버가 UPDATE 로 바꾸는 것은 트리거가 없어 막지 못한다(P2 · 실제 권한에 쓰이지 않는 생성 이력 값).
- `leave_trip` PLANNING guard 는 20260917000004 에서 추가됐다(화면 조건과 DB 조건 일치).
- 실기 E2E(초대 재사용 · 승인 · 나가기 · 위임)는 기존 Final Regression PASS 이후 로직 변경이 guard 추가뿐이라 정책 정의 + 화면 smoke 로 확인.
