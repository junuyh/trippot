## 0. 읽는 법

**ADR 번호.** `ADR-001` 부터 영역별로 묶어 부여했다. 번호는 결정 순서가 아니라 식별자다. 일자 순서는 §1 요약표를 본다.

**상태.**

| 상태 | 뜻 |
|---|---|
| **확정** | 결정이 있고 코드가 그것을 따른다 |
| **코드 선행** | 코드가 먼저 갔고 결정 기록·문서 갱신만 남았다. 되돌릴 계획은 없다 |
| **[검토 필요]** | 아직 결정이 없거나 코드끼리·문서끼리 어긋나 재합의가 필요하다. §3 에 다시 모았다 |
| **폐기** | 한때 결정이었으나 이후 결정으로 대체됐다. §4 에 다시 모았다 |

**결정자.** 팀이 함께 정한 것은 "팀 확정". 문서 commit 작성자가 확인되는 것은 이름을 적었다. 코드 선행 항목은 "담당자(코드 선행)". 확인되지 않는 일자는 "일자 미확인".

**근거 표기.**

| 표기 | 가리키는 곳 |
|---|---|
| `18 §2-3` | `18_서비스비교정리.md` 의 표 행 번호 |
| `README #9` | `docs/README.md` §5 미반영 변경사항의 # 번호 |
| `10 v2 §12` | `10_여행초대정책_v2.md` §12 (다른 문서도 같은 방식) |
| `PR #86` | GitHub PR 번호. 일자는 `origin/develop` merge 일자 |
| `CLAUDE.md 4장` | 저장소 루트 `CLAUDE.md` 의 장 번호 |
| 코드 경로 | 18 문서 근거 열을 그대로 옮긴 것. 행 번호는 18 작성 시점(`develop` `fef9c86`) 기준 |

**영향** 항목의 "종결된 README #" 는 그 결정으로 `docs/README.md` §5 의 해당 항목이 더 이상 유효하지 않거나 해소됐다는 뜻이다. README 자체는 수정하지 않는다(docs 규칙).

#### ADR-002. 목적지는 목록에서만 고른다

- **일자 · 결정자**: 2026-08-28 목록 선택 확정 (README #9, 박현주 commit `44f07ff` · `1a09b2a`) → 목록 밖 도시 미지원은 일자 미확인 · 담당자(코드 선행 후 확정)

#### ADR-003. 여행 스타일 — 3단계, 예산 단계에서, 카테고리별 배수

- **일자 · 결정자**: 배수 규칙 2026-08-28 (README #7, 박현주 commit `44f07ff`) · 입력 위치 2026-09-01 TRIP-03 개편 (팀 확정) · 3단계 축소는 일자 미확인 (코드 선행)
- **문제정의**: ① 단일 배수는 항공(이코노미 기준이면 스타일 영향 거의 없음)과 숙박(3배 넘게 갈림)을 같이 다룰 수 없다. ② 1인 1일 요율에서 반올림하면 오차가 인원×일수만큼 증폭된다. ③ 스타일은 예산 배수인데 STEP 2 에서 고르면 결과가 안 보이고, 직접 입력 방식이면 배수 자체가 무의미하다. ④ 4단계에서는 comfort 와 luxury 차이를 사용자가 못 가른다.
- **의사결정**:
  - 배수는 **카테고리별**. 최종 카테고리 금액에 곱한 뒤 **1,000원 단위 반올림**. `INSURANCE` 는 전 스타일 1.0, `standard` 는 전 항목 1.0.
  - 입력 위치는 **STEP 3(예산)**, **추천 방식일 때만** 묻는다.
  - 단계는 **3단계** budget / standard / comfort (luxury 삭제).
- **근거**: README #7 · 18 §2-5 · 2-6 · 2-7 · `lib/constants/budgetMultiplier.ts:33-93` · `app/trips/new/basic.tsx:6-8` · `budget-fund.tsx:1381-1384` · `lib/constants/status.ts`

- **의사결정**: 용어 체계를 아래로 확정한다. 이것이 최신 Source of Truth 이며, 09-17 의 "초대 수락 · 승인" 은 폐기한다(→ §4).

  | 자리 | 문구 |
  |---|---|
  | 초대 시작 (여행 정보 수정) | `여행 멤버 초대하기` |
  | 링크 공유 (초대 시트 · OS 공유) | `초대 링크 보내기` |
  | 초대 수신 화면 title | `여행 초대` |
  | 수신자 CTA | `참여 의사 보내기` (미가입 `가입하고 참여 의사 보내기` · 재참여 `다시 참여 의사 보내기`) |
  | 수신자 helper | `참여 의사를 보내면 여행장이 확인해요.` / `여행장이 수락하면 여행 준비를 함께할 수 있어요.` |
  | 수신자 전송 완료 | `참여 의사를 보냈어요` / `여행장이 확인하고 있어요.` / `수락되면 여행 준비를 함께할 수 있어요.` |
  | 여행장 알림 상세 CTA (이동만) | `참여 의사 확인하기` |
  | 여행장 홈·여행 홈 배너 | `{닉네임}님이 참여 의사를 보냈어요` · 부제 `참여 의사 N건` · CTA `확인하기` |
  | 여행장 여행 정보 수정 pending item | `{닉네임}님이 참여 의사를 보냈어요` |
  | 여행장 Bottom Sheet 최종 행동 | `수락하기` / `거절하기` |
  | 알림 4종 | `여행 초대가 도착했어요` · `참여 의사가 도착했어요` · `여행 참여가 수락됐어요` · `여행 참여가 거절됐어요` (14 v2 · DB producer 동일) |

- **interaction semantics (이 결정의 핵심)**: 초대 링크를 받은 사용자가 `참여 의사 보내기` 를 눌러도 **즉시 여행 멤버가 되지 않는다.**

  ```
  초대 링크 → 참여 의사 전송 (PENDING) → 여행장 확인 (배너 · 알림 → 여행 정보 수정)
    → 여행장 Bottom Sheet → 수락하기 / 거절하기 → 수락 시 ACTIVE 여행 멤버
  ```

  따라서 다음 표현은 사용자 노출 문구에 쓰지 않는다: **수신자 쪽의 "초대 수락"**, **수신자 쪽의 "승인"**, **이동만 하는 CTA 의 "수락"**. `수락` 은 실제 accept mutation 을 실행하는 최종 행동(`수락하기`)과 그 결과(`수락됐어요` · `수락 대기`)에만 쓴다. navigation-only 버튼은 `확인하기`.
- **근거**: 18 §8-13 · 9-2 · `lib/trip/tripActions.ts`(배너 headline 단일 source) · `components/trip-edit/TripEditForm.tsx` · `components/invite/JoinRequestSheet.tsx` · `lib/notifications/resolveNotificationAction.ts`(알림 상세 CTA) · `lib/notifications/messages.ts` · `20260918000001`(DB producer · 기존 행 backfill 완료, 2026-09-20 read-only 조회로 legacy 행 0 확인)
- **영향**: 코드 14파일 문구만 변경(기능·DB·RLS 무변경). 10 v2 · 12 · 14 v2 의 "참여 요청 · 승인" 표기는 이 ADR 이 우선한다 — 각 문서의 다음 버전에서 갱신 대상. 내부 기술명(`JOIN_REQUESTED` · `accept_trip_join_request` · DB status)은 바꾸지 않는다.
- **상태**: 확정 (2026-09-20 · 팀 테스트 후)

#### ADR-047. RLS 와 GRANT 는 둘 다 있어야 한다

- **일자 · 결정자**: 2026-08-28 · 박현주 (commit `84db244`, 마이그레이션 `20260828000001_grant_anon_access.sql`)
- **문제정의**: RLS 정책만 있고 GRANT 가 없어 `anon` 이 23개 테이블 전부 `42501 permission denied`. `05 v2` §6-1 은 반대로 "`anon` key 만 있으면 모든 행을 읽고 쓸 수 있다" 고 적어 원인을 RLS 쪽에서 찾게 했다.
- **의사결정**: `anon`/`authenticated` 에 GRANT + `alter default privileges`. **RLS 는 행을 거르고 GRANT 는 테이블 접근을 허용한다.** 증상 구분: `permission denied for table` → GRANT / 행 0건 → RLS. 이 GRANT 는 `dev_open_all` 과 짝인 개발용이며 배포 전 RLS 정책 교체와 함께 재검토(→ ADR-048). `service_role` 도 GRANT 는 우회하지 않으므로 Edge Function 이 쓰는 표에 GRANT 를 확인한다.
- **근거**: README #18 · `05_ERD_v3` §6-0 · §6-5 · `CLAUDE.md` 18장 7항
- **영향**: README #18 해소.
- **상태**: 확정

#### ADR-052. `track()` 단일 진입점 — 필요한 이벤트만

- **일자 · 결정자**: 일자 미확인 · 팀 확정 (`CLAUDE.md` 8장 · README #10)
