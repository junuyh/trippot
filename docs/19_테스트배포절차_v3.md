## 3. 안드로이드 — 앱을 고쳤을 때

1. `develop` 최신을 받는다.
2. 사람이 직접 실행한다. **Claude Code 는 명령만 준비하고 실행은 넘긴다** (`CLAUDE.md` 17장 · 권한 차단).
   ```bash
   npx eas build -p android --profile preview
   ```
   서명 키는 EAS 서버(trippots-team)에 있다. 로컬 keystore 파일 없음. 10~20분.
3. 끝나면 expo.dev → trippots-team → trippot → **Builds** → 해당 빌드 → APK 다운로드 링크 복사. 형태: `https://expo.dev/artifacts/eas/….apk`
4. `web/install/index.html` 에서 세 곳을 같이 고친다.
   - 맨 아래 `LINKS.android` 값
   - 안드로이드 카드의 `빌드 N · 10월 1일까지` 만료 문구 — **만료일 = 빌드일 + 14일** (EAS artifact 보관 기간)
   - 상단 `버전 1.0.0 (N) · 날짜`
5. `feature/*` 브랜치 → PR → `develop` 머지 → 자동 배포. PR 미리보기 주소에서 버튼이 새 링크를 가리키는지 확인한다.

알아둘 것
- 이미 깔린 폰은 새 APK 를 받아 그대로 설치하면 업데이트된다(같은 서명 키).
- `expo-updates` 는 네이티브 라이브러리라 **9/17 이전 APK** 는 새 빌드를 받아야 EAS Update 를 받는다.
- 링크 만료 전 재빌드가 어려우면 APK 파일을 구글 드라이브("링크가 있는 모든 사용자")에 올리고 그 링크를 쓴다. GitHub Releases 는 저장소가 비공개라 외부 테스터가 못 받는다.

## 4. 아이폰 — 앱을 고쳤을 때 (EAS Update)

**2026-09-22 부터는 `develop` 에 머지되면 CI 가 자동으로 올린다(§9).** 아래는 CI 가 실패했거나 develop 밖의 것을 올려야 할 때다.

1. `develop` 최신 + `tsc` 통과 상태에서 실행한다. **이 명령은 Claude Code 가 실행해도 된다.**
   ```bash
   npx eas update --branch preview --environment preview --message "<한국어 설명>"
   ```
2. 올린 뒤 Expo Go 고정 주소(§1)로 열어 반영됐는지 확인한다. 시뮬레이터에서는 Expo Go 앱에 조직 계정으로 로그인한 뒤 주소를 연다.
3. 페이지 링크 교체는 필요 없다. 고정 주소는 새 업데이트를 올려도 같다.

테스터 쪽 순서(안내 페이지에 있음): 앱스토어 Expo Go 설치 → expo.dev 무료 가입 → 가입 이메일을 동의 폼에 적음 → **팀이 Viewer 초대** → 초대 수락 → Expo Go 로그인 → 설치 페이지 "Expo Go로 열기".

한계: 홈 화면에 TripPot 아이콘이 생기지 않고 Expo Go 안에서 열린다. 알림 일부 제한. 로그인 복귀 주소가 `exp://`.

대면 대안(테스터가 가입·초대를 귀찮아할 때)
- Expo Go 만 설치: `npx expo start --go --tunnel` → 터미널 QR 을 아이폰 카메라로. 노트북이 켜져 있는 동안만.
- 앱 설치 자체를 거부: 무료 애플 계정 + Xcode 케이블 설치(7일마다 재설치). 절차는 팀 공유 문서 `팀공유_아이폰테스트방법`.

## 5. 건드리면 안 되는 것 (사람 · Claude Code 공통)

| 항목 | 이유 |
|---|---|
| `app.json` 의 `version` · `runtimeVersion` · `updates.url`, `eas.json` 의 `channel` | 바꾸면 Expo Go 고정 주소가 달라진다. `web/install` · `web/invite` 의 값도 같이 고쳐야 하고, 기존 APK 는 새 업데이트를 못 받는다. **팀 합의 후에만** |
| `web/invite/index.html` 의 `EXPO_PROJECT_ID` · `RUNTIME_VERSION` · `CHANNEL` | `app.json` / `eas.json` 과 같아야 한다 |
| `expo` SDK 54 → 55 이상 업그레이드 | 스토어판 Expo Go 가 SDK 54 라 테스터가 열 수 없게 된다. 테스트 기간 중 금지 (§8) |
| `lib/invite/tripInviteLink.ts` 의 `TRIP_INVITE_WEB_BASE` | 착륙 페이지 도메인. 바뀌면 여기 한 곳만 |
| `web/` 에 분석 스크립트 · 외부 요청 추가 | 테스터 안내 페이지에 개인정보 안내와 다른 수집이 생긴다. 외부 요청은 Google Fonts 뿐 |
| 초대 토큰을 `?t=` 쿼리로 | 서버 기록에 남는다. 반드시 `#` fragment |
| `web/` 페이지에서 토큰 저장 · 전송 | 페이지는 토큰을 저장하지 않는다 |
| Cloudflare Pages 프로젝트 설정 변경 | 리더 개인 계정. production branch `develop` · 빌드 명령 없음 · output `web` |
| 설치 페이지의 개인정보 안내 표 내용 | 코드가 실제로 모으는 항목과 맞춰 적은 것. 앱이 새 정보를 모으면 표도 같이 고친다 |

## 8. Expo Go 버전 규칙 (테스터 · 팀원 시뮬레이터 공통)

이 앱은 **Expo SDK 54** 다(`package.json` `expo ~54.0`). Expo Go 는 SDK 마다 다른 앱이라 **버전이 맞아야 열린다.**

| 어디 | 어떤 Expo Go | 맞추는 법 |
|---|---|---|
| 테스터 아이폰 · 안드로이드 실기기 | 앱스토어 · Play 스토어의 Expo Go = **SDK 54 전용** (Expo 2026-05 공지: 스토어판은 SDK 54 로 유지, 55 이후는 스토어에 못 올라감) | 스토어에서 받으면 된다. 우리 앱이 54 라 그대로 열린다 |
| 팀원 iOS 시뮬레이터 | Expo CLI 가 SDK 에 맞는 Expo Go 를 직접 내려받아 설치 | `npx expo start` → `i`. 버전이 다르면 CLI 가 "Expo Go X is recommended for SDK 54 … Install the recommended version?" 을 묻는다 → **Y** |
| 팀원 Android 에뮬레이터 | 위와 같음 | `npx expo start` → `a`. 같은 프롬프트에 **Y**. 프롬프트가 안 뜨면 에뮬레이터에서 Expo Go 를 지우고 `a` 를 다시 누른다 |

⚠️ **SDK 를 54 위로 올리면 테스트가 막힌다.** 스토어판 Expo Go 가 54 라 테스터 폰에서 EAS Update 를 열 수 없고, 55 이후 Expo Go 는 `eas go`(TestFlight · 애플 유료 계정 필요)로만 받을 수 있다. **테스트 기간(~10/31) 동안 `expo` 메이저 업그레이드 금지.** `npx expo install --fix` 도 SDK 를 바꾸지는 않지만, `expo@55` 이상을 요구하는 라이브러리는 넣지 않는다.

⚠️ Android 에뮬레이터에 Play 스토어에서 Expo Go 를 깔지 않는다. 다른 프로젝트(SDK 57·58)로 쓰던 에뮬레이터에는 다른 버전이 남아 있을 수 있다 — 위 프롬프트가 해결한다. `--offline` 로 시작하면 버전 검사를 건너뛰어 그냥 실패하니 온라인으로 시작한다.

참고: 2026-09-03 부터 **SDK 57 iOS Expo Go** 는 개발 서버 접속에도 로그인이 필요하다. 스토어판(SDK 54)에는 아직 적용되지 않았다. EAS Update 는 5월부터 조직 멤버 로그인이 필요하다(§4).

## 9. 자동 반영 (CI) — `develop` 머지 → `eas update`

파일: `.github/workflows/eas-update-preview.yml` (2026-09-22)

| 언제 | 무엇을 | 건너뛰는 경우 |
|---|---|---|
| `develop` 에 push(머지) 될 때 | `pnpm install` → `tsc` → `eas update --branch preview --environment preview` · 메시지는 `CI · <머지 커밋 제목>` | `docs/` · `web/` · `*.md` · `.github/` 만 바뀐 머지 |
| Actions 탭에서 수동 실행(workflow_dispatch) | 같음 | — |

전제 조건(한 번만 · Expo 조직 Admin 이상 + GitHub 저장소 Admin)
1. expo.dev → **trippots-team** → Settings → **Access tokens** → robot user 만들고 토큰 발급. 역할은 **Developer** 면 된다.
2. GitHub → `junuyh/trippot` → Settings → Secrets and variables → Actions → **New repository secret** → 이름 `EXPO_TOKEN`, 값은 위 토큰.
3. 토큰이 없으면 워크플로 첫 단계가 안내 문구와 함께 실패한다. 앱은 안 바뀐다.

환경 변수
- `EXPO_PUBLIC_SUPABASE_URL` · `EXPO_PUBLIC_SUPABASE_ANON_KEY` · `EXPO_PUBLIC_AMPLITUDE_API_KEY` 는 EAS 서버의 **preview 환경**에 있다(`eas env:list --environment preview`). CI 는 `--environment preview` 로 그 값을 받는다.
- `EXPO_PUBLIC_TEST_BUILD=1` 은 서버에 없어 워크플로가 직접 준다(가상 계좌 시연용 · `lib/constants/testBuild.ts`).

확인하는 법
- GitHub → Actions → "EAS Update (preview) on develop" 이 초록인지.
- expo.dev → trippot → Updates → preview 브랜치 맨 위가 방금 머지 커밋 제목인지.
- Expo Go 고정 주소(§1)로 열어 바뀐 화면이 보이는지. 이미 열려 있던 앱은 완전히 닫고 다시 연다.

여전히 사람이 하는 것
- **안드로이드 APK** — CI 가 만들지 않는다. `eas build` 는 사람이 직접(§3). 아이폰만 자동이다.
- `app.json` `version` 변경 — 바꾸면 runtime-version 이 달라져 기존 고정 주소로 새 업데이트가 안 보인다. 팀 확인 후에만(§5).
- develop 밖 브랜치를 테스터에게 보여 주고 싶을 때 — `eas update --branch preview` 를 직접 올린다(§4). 단 다음 머지 때 CI 가 덮어쓴다.
